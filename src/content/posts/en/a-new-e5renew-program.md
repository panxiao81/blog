Microsoft’s been really generous about letting us freeload an E5 Developer subscription, which gives access to almost all of the features. Of course, this is meant to be a sandbox for 365 ecosystem developers, but as long as it detects active use, you can renew it every 60 days, so in theory you can keep it going forever.

As everyone knows, there are already some pretty mature programs out there, but I didn’t want to spin up a Windows Server just to keep one of those running. And that famous Renew X thing somehow uses the Password flow, which always felt a little sketchy to me security-wise, since it’s basically asking me to hand over my password. So, in the grand old DIY tradition, I vibed one up.

I actually wrote the prototype of this thing completely myself. I first tried using .NET, but I also wanted it to run on a low-resource machine, and I’m not that familiar with the .NET ecosystem anyway. (At the very beginning I wanted to use Java, but I pretty quickly talked myself out of that.) So the current prototype is written in Go. The later refactoring, testing, and so on were handed over entirely to AI; I only did some of the architecture design.

The current version still depends on a database. The original version was supposed to run on OCI, so it only supported MySQL at first (OCI Free Tier has MySQL instances). Later I moved it to local running, and the machine I’m using locally only has PostgreSQL, so right now this program only supports those two databases. I’m not planning to add SQLite support for now. The whole database access layer is handwritten SQL + code generated by sqlc, which means every time I add another backend I need to write another set of SQL and also change the Repository layer code to add support. Since I don’t currently need SQLite support, I’m just not bothering with it.

I’m not planning to turn my server into a shared service for everyone to use. Even though the web page is exposed to the public internet, you can’t get into the backend unless you log in with my Entra tenant account. So if you want to use it too, please deploy it yourself. There’s already a packaged Docker image on ghcr.io, plus a Helm Chart, so feel free to use those as references.

I didn’t write this in the docs, but I figure it shouldn’t be too hard for you folks to have whatever AI Agent you like read AGENTS.md and then have AI install it for you, right? At the very least, get an OpenClaw going, no? (

Since there’s a Web UI, I used Authorization Code flow for the auth process. In theory, it’d probably be possible to do a bit of refactoring and add Device flow too, but since there’s already a web page, there’s not much point, right?

For now, the name is [e5renew](https://github.com/panxiao81/e5renew).
