我们总能听到有人说，在中国，CentOS 或 RHEL 比其他发行版，比如 Ubuntu 或别的什么，都更稳定。类似地，当我们讨论包管理器时，也有人认为 APT 或 Pacman 比 YUM 更好。但这些说法真的对吗？我大多数都不认同。

## 系统稳定性，还是 ABI 稳定性？

有人说，CentOS 比别的更稳定。但如果你问他们为什么更稳定，他们可能会说，因为 CentOS 的源代码来自 Red Hat，而且已经被 RHEL 用户充分测试过了。

对于这些观点，我得说，这话没错。可有些系统管理员会更新自己的 Linux 内核来获得新功能，甚至还有人会自己编译 Glibc 和 GCC，好在像 CentOS 6 这种老系统上装更新的软件，比如装 docker。

如果你曾经尝试自己搭建过 Linux From Scratch，你应该知道，Linux 内核、系统里的 Glibc，以及 GCC 编译器的版本都必须是稳定的，而且所有软件也都应该用那个版本来编译。我们在做这些的时候，整个系统就可以因为相同的系统 ABI 而被称为稳定。

Linux 不像 Windows 或 FreeBSD，用户正在使用的软件应该和系统一起提供。这一切都是因为 Linux 的 ABI 并不稳定。而整个系统是由一堆开源软件拼起来的，其中大多数都来自 GNU 项目。

也正因为如此，很多系统管理员都很害怕升级系统，因为他们不知道系统升级之后还能不能正常启动，软件还能不能像以前一样运行。尤其是大版本升级的时候。甚至有人说，Linux 上最稳定的 ABI 是通过 Wine 使用的 win32 ABI，特别是对 Linux 桌面用户来说。

另外，Linux 发行版的维护者必须用更新版本的内核和 Glibc 去编译软件，测试它，然后把编译好的二进制文件随 Linux 发行版一起发布。只有连同这些软件一起、被完整测试过的整个系统，才配得上叫稳定。

所以，正如我上面说的，如果你更新了系统内核或者 Glibc，你其实就已经破坏了系统的稳定性，而此时，这个系统也就不能再被称为稳定了。

## 现实世界的问题

但在现实里，大多数时候，发行版自带的软件包并不够我们用，我们必须使用一些第三方软件。如果你从厂商那里买软件，他们可能已经测试过它和你正在用的系统是否兼容。但开源软件呢？抱歉，软件本身“IS PROVIDED "AS IS", WITHOUT WARRANTY OF ANY KIND”

## 还有一些其他情况

同样地，当有人谈到包管理器时，他们会说“APT 比 yum 更好”或者“Pacman 是最好的”。从技术上讲，APT 并不好，因为它在解决依赖和下载速度方面的能力一般。但 DNF，也就是 YUM 的下一代，实际上比 APT 更好。那些人之所以说“更好”，真正的原因是 Ubuntu（或者其他基于 Debian 的发行版）官方仓库里的软件包数量比 CentOS 更多，或者发行版自带的软件版本更新。

有些人不喜欢 CentOS Stream，他们其实是把 CentOS Stream 和 Arch-like 的滚动发行版搞混了。CentOS Stream 确实是滚动发行版，但没那么“滚动”；它仍然有一个大版本，而这个大版本里的主要软件包也还是一样的。

最后，你当然可以说 RHEL 或任何其他 RHEL 衍生发行版是稳定的，但我想让你知道的是，当我们说“稳定”时，我们真正说的到底是什么。
