Microsoft はずっと気前よく、E5 Developer サブスクリプションをタダで使わせてくれていて、ほぼ大部分の機能が使える。もちろんこの環境は Microsoft 365 エコシステムの開発者向けサンドボックスなんだけど、積極的な利用が検知されさえすれば 60 日ごとに更新できるので、理論上は無限に延長できる。

ご存じの通り、ネット上にはすでに成熟したプログラムがいくつかある。でも、これを動かすためだけに Windows Server を1台用意するのはやりたくなかった。それに、某有名な Renew X がなんと Password flow を使っていて、どうにも安全性がイマイチに感じた。だって結局、こっちがパスワードを渡すことになるわけだし。そんなわけで、「自分のことは自分でやる」の精神で、Vibe で1本作った。

実はこのプログラムの原型は完全に自分で書いた。最初は .NET で試そうとしたんだけど、低リソースなマシンで動かしたかったのと、そもそも .NET エコシステムにあまり詳しくなかったのとで断念した。というか最初は Java でやろうと思ってたんだけど、すぐに自分で却下した。で、今の原型版は Go で書いてある。以降のリファクタリングとかテストとかは完全に AI に任せていて、自分はちょっとしたアーキテクチャ設計をしただけだ。

今のバージョンはまだデータベースに依存している。最初の版は OCI 上で動かすつもりだったので MySQL しか対応していなかった（OCI Free tier には MySQL インスタンスがある）。その後ローカル実行に移したんだけど、ローカルのホストには PostgreSQL しかなかったので、今はこのプログラムはこの2つのデータベースだけをサポートしている。SQLite を追加するつもりは今のところない。データベースアクセス層は手書き SQL + sqlc で生成したコードでできていて、つまりバックエンドを1つ追加するたびに SQL をもう1セット書く必要があるし、Repository 層のコードも対応させる必要がある。今のところ SQLite のサポートが必要ないので、そこはやらない。

今のところ、このサーバーをみんな向けの共有サービスとして公開するつもりはない。Web ページ自体は公開してあるけど、僕の Entra テナントアカウントでログインしないとバックエンドには入れないので、使いたい人は各自でデプロイしてほしい。ghcr.io にはパッケージ済みの Docker イメージと Helm Chart がもう置いてあるので、参考にして使ってもらえればいい。

ドキュメントには書いてないけど、適当な AI Agent に AGENTS.md を読ませて、そのまま AI に入れてもらうくらいなら、たぶん別に難しくもないでしょ。少なくとも OpenClaw くらいは余裕だよね（

Web UI があるので、検証フローには Authorization Code flow を使った。理屈の上では、ちょっとリファクタリングして Device flow を追加するのも不可能ではない。でも、Web ページがあるなら、わざわざそこまでやる必要もないかな。

名前はひとまず [e5renew](https://github.com/panxiao81/e5renew) ってことにしておく。
